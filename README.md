================================================================================
POSTGRESQL + TIMESCALEDB + МОНИТОРИНГ
(Prometheus & Grafana)
================================================================================

Кроссплатформенный стек для сбора и хранения данных с автоматическим мониторингом.
Работает на Windows (Docker Desktop) и Linux (Debian/Ubuntu).

ЧТО ВХОДИТ В СТЕК
================================================================================

TimescaleDB (PostgreSQL 17) – основная база данных с расширением для временных рядов.

PostgreSQL Exporter – сбор метрик производительности.

Prometheus – хранилище метрик.

Grafana – визуализация с преднастроенным дашбордом (ID 9628) для PostgreSQL.

Все сервисы описаны в docker-compose.yml и запускаются одной командой.

ТРЕБОВАНИЯ
================================================================================

Docker (19.03+) и Docker Compose (плагин или отдельный binary).

На Windows – Docker Desktop с WSL2 (рекомендуется) или Hyper-V.

На Linux – Docker Engine + Docker Compose Plugin.

БЫСТРЫЙ СТАРТ
================================================================================

Клонируйте репозиторий

git clone <your-repo-url>
cd pg_with_mon_in_docker

Создайте файл .env из шаблона cp .env.example .env

Отредактируйте .env, задав свои пароли и пути. Примеры:

Для Windows (абсолютный путь на диске D:): DATA_PATH=D:/../postgresql

Для Linux (относительный путь внутри проекта): DATA_PATH=./pg_data

Остальные переменные (порты, пользователь БД) можно оставить по умолчанию или изменить при необходимости.

Запустите стек docker-compose up -d

При первом запуске автоматически:
    - Создадутся необходимые тома для данных.
    - Выполнятся SQL-скрипты из init-db/ (создание таблиц, расширений, политик).
    - Запустятся Prometheus, Grafana и экспортер.
    - Grafana автоматически подключится к Prometheus и импортирует дашборд.

Проверьте логи docker-compose logs -f postgres_timescale

Убедитесь, что все сервисы запустились без ошибок. Если в логах нет ошибок, база готова к работе.

Подключитесь к БД с хоста psql -h localhost -U login_db -d pass_db

МОНИТОРИНГ (АВТОМАТИЧЕСКАЯ НАСТРОЙКА)
================================================================================

После запуска откройте браузер:

Grafana: http://localhost:3000
Логин: admin, пароль: admin (при первом входе система попросит сменить пароль).

Дашборд "PostgreSQL Database" уже импортирован и доступен в разделе Dashboards.

Он показывает:
    - количество активных / простаивающих сессий
    - транзакции (коммиты / роллбэки)
    - операции INSERT / UPDATE / DELETE / SELECT
    - Cache Hit Rate
    - блокировки
    - статистику по контрольным точкам
    - использование памяти и CPU
    - и многое другое.

БЭКАП БАЗЫ ДАННЫХ
================================================================================

Настройте автоматическое резервное копирование через cron (Linux) или Планировщик задач (Windows)
    - docker exec binance-postgres pg_dump -U collector binance > /path/to/backup/backup_$(date +%Y%m%d).sql
Для сжатия:
    - docker exec binance-postgres pg_dump -U collector binance | gzip > backup_$(date +%Y%m%d).sql.gz

БЕЗОПАСНОСТЬ
================================================================================

На Linux настройте фаервол (UFW), открыв только необходимые порты:

sudo ufw allow OpenSSH
sudo ufw allow 5432/tcp # PostgreSQL (только если нужно внешнее подключение)
sudo ufw allow 3000/tcp # Grafana
sudo ufw allow 9090/tcp # Prometheus (опционально)
sudo ufw enable

Для продакшена рекомендуется ограничить доступ к портам с помощью
ufw allow from <IP-адрес>

Используйте надёжные пароли в .env и никогда не публикуйте их в открытом доступе.

УСТРАНЕНИЕ НЕПОЛАДОК
================================================================================

Проблема: Ошибка прав доступа к папке данных на Linux
Решение: выполните sudo chown -R 999:999 ./pg_data (UID 999 – пользователь postgres в контейнере).

Проблема: Скрипты инициализации не выполнились
Решение: проверьте, что файлы в init-db/ имеют расширение .sql и названия начинаются с цифр (01, 02, …).

Проблема: Grafana не видит источник данных
Решение: убедитесь, что в grafana/provisioning/datasources/prometheus.yml указан url: http://prometheus:9090.

Проблема: Дашборд не импортируется
Решение: проверьте, что JSON-файл лежит в grafana/dashboards/ и не повреждён.

Проблема: Конфликт портов
Решение: измените порты в .env (например, POSTGRES_PORT=5433, GRAFANA_PORT=3001).
